## 1. 产品定位与目标

一款通过“点击选中网页模块”提取图片的浏览器插件。用户在网页上选择一个区域对应的 DOM 元素，插件提取该元素及其后代引用的图片，在浏览器侧边栏展示缩略图和图片链接，并提供大图预览与图片详情。

核心流程：**打开插件 → 预览并锁定模块 → 调整范围并确认提取 → 浏览缩略图和链接 → 查看详情或复制链接。**

首版目标：

1. 用户无需打开开发者工具，即可提取指定模块中的常见网页图片。
2. 用户能够确认提取范围，避免混入页面其他区域的图片。
3. 每条结果同时提供可识别的图片预览和可复制的图片地址。
4. 对未加载、无法预览、不支持的资源给出明确状态，避免让用户误认为提取已完整覆盖所有图片。

这里的“提取”指发现页面已经暴露的图片资源引用；不包含模块截图、图像识别或寻找服务器上未公开的原始文件。

## 2. 用户与典型场景

| 用户 | 场景 | 需要得到的结果 |
| --- | --- | --- |
| 设计师、内容运营 | 选择网页中的横幅、图文区或画廊 | 快速查看图片并复制对应地址 |
| 电商运营 | 选择商品列表或商品详情模块 | 提取该模块商品图，排除页头、广告等其他区域 |
| 前端开发者 | 选择使用背景图或响应式图片的模块 | 查看图片来源、实际选用地址与页面显示尺寸 |
| 普通用户 | 选择文章配图区域 | 通过缩略图找到需要的图片，查看大图和链接 |

示例：用户选择含 12 张商品卡片的列表容器；其中同一图片出现 3 次。结果按地址去重，并记录每张图片的出现次数。容器之外的站点 Logo 不进入结果。

## 3. 术语与基本规则

| 术语 | 定义 |
| --- | --- |
| 模块 | 用户选中的一个 DOM 元素及其后代；可以是单张图片、卡片、列表、横幅或整个正文容器 |
| 模块选取 | 根据鼠标所在位置选中元素，可向上扩大到父级，或退回之前的子级 |
| 资源 | 一个规范化后的图片 URL，对应结果中的一张卡片 |
| 来源位置 | 图片在页面中的一个引用位置，包括元素、引用类型和显示尺寸 |
| 当前图片地址 | 浏览器实际选用的图片地址；不等于服务器保存的最大尺寸原文件 |
| 固有尺寸 | 浏览器返回的 `naturalWidth × naturalHeight`，单位为 CSS 像素，不保证等于文件编码像素尺寸 |
| 显示尺寸 | 来源元素在当前页面中的边界框尺寸；背景图展示的是承载元素尺寸 |
| 提取快照 | 点击时启动、在一次扫描期间取得的结果；页面继续变化不会自动改变已完成的结果 |

`currentSrc` 可用于获取响应式图片实际选用的地址，但有地址并不表示图片已成功加载。[MDN：currentSrc](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/currentSrc)

固有尺寸采用浏览器可取得的信息，不将其标为“原文件像素尺寸”。[MDN：naturalWidth](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/naturalWidth)

## 4. 版本范围与优先级

**P0：首版必须实现；P1：后续增强；P2：远期探索。**

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 工具栏启动、浏览器侧边栏 | P0 | 页面与结果并排展示 |
| 元素悬停高亮、点击选取、父子级调整 | P0 | 一次选择一个模块 |
| 普通 `img`、`picture` 当前图片提取 | P0 | 以实际选用地址为主 |
| CSS 背景图、伪元素背景图提取 | P0 | 支持多层 `background-image` 中的 `url()` |
| 常见懒加载属性兼容 | P0 | 明确识别范围和候选状态 |
| URL 规范化、去重、来源记录 | P0 | 按地址去重，不按图像内容去重 |
| 缩略图、链接、详情、大图缩放 | P0 | 详情包含上一张、下一张 |
| 单条复制、复制全部链接、打开图片地址 | P0 | 可独立于预览成功与否使用 |
| 重新选择、重新提取、取消、异常提示 | P0 | 结果按标签页隔离 |
| 单张下载、批量下载、导出 CSV/JSON | P1 | 后续按需添加权限与失败恢复 |
| 搜索、格式/尺寸筛选、多选、排序 | P1 | 首版使用首次发现顺序 |
| 枚举 `srcset` 与 `picture` 中全部候选版本 | P1 | 首版只提取当前选用资源 |
| 开放 Shadow DOM、同源 iframe 内部提取 | P1 | 单独完成选取、遍历和坐标适配 |
| 经用户授权的图片域名请求与预览增强 | P1 | 不承诺解决站点鉴权或防盗链 |
| `data:`、`blob:`、内联 SVG 导出 | P1 | 需补充大小、生命周期与安全规则 |
| 多模块合并、历史记录、Firefox 适配 | P1 | 独立迭代，不作为首版验收条件 |
| 自动滚动加载、网络资源捕获、内容去重 | P2 | 评估收益后再决定 |

首版不包含：账号、云端存储、AI 图片识别、网页截图、Canvas/WebGL 导出、视频帧提取、跨域 iframe 内部扫描、闭合 Shadow DOM、绕过登录或访问控制。

## 5. 端到端用户流程

1. 用户打开普通 HTTP/HTTPS 网页，点击浏览器工具栏插件图标。
2. 浏览器打开侧边栏；插件获得当前标签页临时访问能力，显示“选择网页模块”按钮。
3. 用户点击按钮，进入选择模式；页面显示悬停边框和简短操作提示。
4. 鼠标移动到目标模块；需要扩大范围时按 `↑` 选择父级，按 `↓` 回到刚才的子级。
   指向标题或文字时可保守推荐附近含图模块，直接指向图片保持精确范围；原始命中元素仍可通过层级路径或 `↓` 返回。悬停稳定后展示含背景和伪元素的图片元素预估数，预估未按 URL 去重，不能代替最终结果；嵌入区域在选取时提示读取边界。
5. 用户单击当前高亮区域或按 Enter 锁定；插件阻止这次点击触发原网页跳转或提交。锁定后鼠标移动不改变范围，显示完整工具条，可通过层级路径或 ↑ / ↓ 调整；“重新选取”回到悬停预览。
6. 用户点击“提取”或按 Enter 确认后，侧边栏逐步展示结果；扫描结束后显示去重图片数、引用次数与扫描状态。工具条优先放在选区外侧，空间不足时停靠视口边缘，范围调整和滚动不改变锚点。
7. 用户浏览缩略图和链接，点击卡片查看详情，或复制链接、打开图片地址。
8. 用户可重新提取当前模块，或重新选择另一个模块。

特殊分支：

- 选择模式按 `Esc`：退出选择，恢复页面交互；已有结果保持不变。
- 模块无图片：显示空结果和调整模块范围的入口。
- 页面不允许访问：显示原因，禁止进入选择模式。
- 图片预览失败：保留卡片和链接，可重试、复制或打开地址。
- 页面发生导航：停止当前任务，旧结果标记为“来自上一页面”，不可直接对旧模块重新提取。

## 6. 交互与页面结构

### 6.1 侧边栏

首版主界面使用浏览器侧边栏。原网页上的覆盖层只承担模块选取和范围提示，不承担结果管理。Chrome 的 `sidePanel` 支持在网页旁显示扩展页面；Edge 也提供相应侧边栏能力。[Chrome Side Panel](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)、[Edge Sidebar](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/sidebar)

文字线框：

```text
┌─────────────────────────────────────┐
│ 模块取图               [选择模块]   │
│ 来源：example.com / 商品列表        │
│ 模块：section.products             │
│ [扩大到父级] [返回子级] [重新提取]   │
├─────────────────────────────────────┤
│ 12 张图片 · 14 处引用 · 扫描完成     │
│ [复制全部链接]                      │
│ ┌────────────┐ ┌────────────┐       │
│ │ 缩略预览   │ │ 缩略预览   │       │
│ └────────────┘ └────────────┘       │
│ 图片名 / 尺寸   图片名 / 尺寸       │
│ https://...    https://...          │
│ [复制][详情]   [复制][详情]         │
└─────────────────────────────────────┘

详情视图：返回列表 → 大图与缩放 → 图片信息 → 链接操作
```

- 宽度由浏览器控制；在约 320～600 CSS 像素范围内适配，窄屏一列、宽屏两列。
- 初始页面显示简短说明和主按钮，避免空白侧边栏。
- 来源区显示页面标题、域名、模块标签摘要和提取时间。
- 模块摘要仅用于辨认，不要求用户理解 CSS 选择器。
- 重新选择默认替换当前结果，不累积多个模块。

### 6.2 模块选取

**FR-01：进入与退出**

- 只有用户点击“选择网页模块”后才捕获页面选取事件。
- 重复启动不得创建多个覆盖层或重复注册监听器。
- 退出、取消、导航或异常时移除高亮与事件监听，恢复光标。
- 在选择模式内拦截指针点击相关事件，避免此次操作触发网页链接、按钮、表单或拖拽。
- 覆盖层不进入扫描结果，不改动业务 DOM 的结构、属性或原样式。

**FR-02：命中与高亮**

- 默认高亮鼠标位置最深的可选元素，边框随滚动与窗口尺寸变化更新。
- 提示条显示元素标签与边界框尺寸，例如 `section · 1180 × 640`。
- 覆盖层本身不参与页面元素命中检测。
- `↑` 沿父级扩大范围，最大到 `body`；`↓` 只沿本次保存的路径回到之前的子级。
- 鼠标移动到其他元素后，重新建立调整路径。
- 点击确认后自动扫描；侧边栏也提供“扩大到父级”“返回子级”，调整后重新扫描。
- 涉及边界：首版在 iframe 与 Shadow DOM 宿主处停止深入；能识别时提示范围限制。

### 6.3 缩略图与结果列表

**FR-03：结果卡片**

每条卡片必须展示：

- 缩略预览；使用等比完整显示，不裁剪图片主体；透明图采用棋盘格背景。
- 文件名或替代标题；优先 URL 路径末段，其次 `alt`，最后“图片 N”。
- 图片地址摘要；允许换行或省略，完整地址在详情中可选择、可复制。
- 可取得的固有尺寸；未知时显示“尺寸未知”。
- 来源类型，例如“图片标签”“背景图”“懒加载候选”。
- 复制链接、查看详情入口。
- 状态：待加载、加载中、可预览、预览失败；有重复引用时显示出现次数。

列表按图片首次被发现的顺序排列。首屏优先加载，可视区域之外的缩略图延迟加载。扫描完成和预览加载完成是两个独立状态。

**FR-04：批量复制**

- “复制全部链接”复制当前结果集全部去重后的 HTTP/HTTPS 地址，一行一个，包括预览失败条目。
- 首版无筛选功能，因此复制范围就是当前提取结果。
- 复制成功显示短提示；失败显示可选中的文本区域，允许用户手动复制。
- 不因为复制操作自动下载或打开图片。

### 6.4 图片详情与大图预览

**FR-05：详情**

点击缩略图或“详情”进入侧边栏内部详情视图。返回列表时保留滚动位置。

| 信息 | 展示规则 |
| --- | --- |
| 大图 | 默认适应容器；支持 25%～400% 缩放、100%、恢复适应；放大后可滚动查看 |
| 当前序号 | 例如“3 / 12”，支持上一张、下一张；首尾按钮禁用，不循环 |
| 图片完整地址 | 原样展示，支持选择、复制、在新标签页打开 |
| 文件名 | 从 URL 路径推导；无合理文件名则显示“未知” |
| 格式 | 首版按扩展名推测，标注“推测”；无法判断时显示“未知” |
| 固有尺寸 | 来自来源图片或预览图片，记录获取来源；两者不一致时分别显示 |
| 页面显示尺寸 | 首个来源元素的边界框尺寸；背景图标为“承载元素尺寸” |
| `alt` | 存在时展示，不存在则显示“未提供” |
| 来源类型 | 支持同一资源关联多个类型 |
| 出现次数 | 所有合并引用的数量；最多列出前 20 个来源详情 |
| 来源页面与时间 | 页面地址、标题与提取时间 |
| 资源状态 | 预览状态、是否懒加载候选、来源是否已失效 |

首版不显示无法可靠获取的文件字节大小、真实 MIME 类型或编码像素尺寸。打开图片地址使用“打开图片地址”文案，不使用可能误导的“查看原图”。

详情预览失败时仍展示元数据与链接，支持一次手动重试；不无限自动重试。

## 7. 图片提取规则

### 7.1 扫描范围

**FR-06：范围规则**

- 扫描选中元素本身与其普通 DOM 后代。
- 包含已存在于 DOM 中的隐藏、离屏元素及轮播未展示的幻灯片；来源详情标注其当前是否显示。
- 不扫描模块的祖先、兄弟节点，也不因为视觉重叠而收录模块外的图片。
- 首版不进入任何 iframe 或 Shadow Root；经过边界时显示可检测到的限制提示。闭合 Shadow Root 可能无法识别，不承诺精确统计。
- 不自动滚动、不点击轮播、不触发网站“加载更多”，不强制改变页面图片的 `src`。
- 未插入 DOM 的虚拟列表图片、网站脚本运行后才生成的地址无法提前发现。
- 扫描期间 DOM 仍可能变化；不冻结网页，结果不是严格同一瞬间的页面快照。

### 7.2 支持的图片来源

| 来源 | 首版规则 |
| --- | --- |
| `<img>` | 优先非空 `currentSrc`，否则有效 `src`；记录当前加载状态 |
| `<picture>` | 读取内部 `<img>` 的当前地址，不额外枚举全部 `<source>` |
| 原生 `loading="lazy"` | 地址已在 `src/currentSrc` 中时直接提取，不要求先滚动进视口 |
| 自定义懒加载 | 兼容 `data-src`、`data-original`、`data-lazy-src`；作为明确标注的候选引用 |
| CSS 背景图 | 读取计算样式 `background-image` 中各层的 `url()` |
| `::before`、`::after` | 仅在伪元素生成时提取其计算背景中的 `url()` |
| 外链 SVG、GIF、WebP、AVIF 等 | 作为普通 HTTP/HTTPS 图片资源处理；能否解码取决于浏览器 |

懒加载属性规则：

1. 每个 `<img>` 收录一个当前图片地址。
2. 同时检查上述三个明确列出的属性；不同于当前地址的有效 URL 可作为候选资源收录，并显示“懒加载候选”。
3. 候选不覆盖当前图片，也不被描述为已展示的图片；同地址最终合并。
4. 不遍历任意 `data-*` 属性，不猜测占位图，不擅自删掉小图。
5. 自定义 `data-srcset`、CSS `image-set()` 候选、`content: url()`、CSS mask、border-image、SVG `<image>`、内联 SVG 首版不在支持范围。

计算样式可通过 `getComputedStyle` 读取，并可针对伪元素查询；实现须正确解析 CSS 的 URL 值，不用简单按逗号拆分背景字符串。[MDN：getComputedStyle](https://developer.mozilla.org/en-US/docs/Web/API/Window/getComputedStyle)

### 7.3 地址规范化与去重

**FR-07：URL 规则**

- 相对地址以来源元素所在文档的 `baseURI` 解析；尊重页面 `<base>` 设置。
- 支持协议相对地址；最终只接收 `http:`、`https:`。
- 空地址、无效地址、其他协议不进入可用资源列表；汇总显示“跳过 N 处不支持或无效引用”。
- `data:`、`blob:` 首版仅计入跳过状态，不承诺可复制为长期有效图片地址。
- 以浏览器 URL 解析后的完整字符串为去重键，保留参数、参数顺序与 fragment；不得移除签名或尺寸参数。
- 相同 URL 出现在多个元素或来源类型中，合并为一张卡片并保留引用数量。
- 同一元素同一属性同一 URL 只计一次；当前地址和懒加载属性属于不同引用位置。
- 不把不同 URL 的同内容图片合并，也不自动合并缩略图与大图版本。
- 不修改 URL 猜测高清图，不主动跟踪重定向以合并资源。

### 7.4 更新规则

**FR-08：重新提取**

- 用户手动滚动加载图片后，点击“重新提取”，对原模块重新扫描并替换结果。
- 按钮扫描期间禁用重复触发；“取消”始终可用。
- 若模块被网站替换或移除，提示“原模块已失效，请重新选择”。
- 页面 URL 变化或文档导航后，将旧结果标为过期；即使同源授权仍有效，也需重新选择模块。
- 首版不持续监听图片变化，不在后台无限增量采集。

## 8. 状态、异常与边界

页面状态：`待选择 → 选择中 → 提取中 → 有结果 / 无结果 / 部分完成 / 失败`。

详情是有结果状态下的子视图；过期是旧结果的附加标记。每张图片的预览状态独立维护。

| 场景 | 用户提示与行为 |
| --- | --- |
| 无图片 | “该模块未发现支持的图片，可扩大选取范围或滚动加载后重试。” |
| 仅发现不支持的资源 | 显示无可用结果，并展示跳过引用数量与类型 |
| 预览失败 | 保留链接；“图片暂时无法预览，可重试或打开图片地址。”不直接推断具体失败原因 |
| 浏览器内部页、扩展商店等受限页 | “当前页面不允许插件读取，请在普通网页使用。” |
| `file:`、PDF 查看器 | 首版不支持，说明支持 HTTP/HTTPS 普通 HTML 网页 |
| iframe / Shadow DOM 边界 | “首版不读取此嵌入区域内部内容。” |
| 内容脚本注入失败 | 显示可重试错误；无授权时引导再次点击工具栏图标 |
| 用户取消提取 | 终止扫描，丢弃本次未完成结果，保留上次完成结果 |
| 页面导航、来源标签页关闭 | 取消在途任务；前者标旧结果过期，后者清理对应任务与结果 |
| 切换标签页 | 退出旧标签页的选择模式、取消未完成扫描；新标签页展示自己的结果或待选择状态 |
| Service Worker 重启 | 恢复已完成结果；未完成任务标为已中断，允许重新提取 |
| 达到扫描或容量上限 | 明确显示“部分完成”与原因，不使用“全部图片已提取” |

旧任务的消息不得覆盖新标签页或新选区的结果。取消任务也必须释放覆盖层、监听器和图片加载队列。

## 9. 技术方案评估与选择

### 9.1 方案比较

以下为针对本产品的工程判断，不是性能测试结论。

| 方案 | 优点 | 需要承担的工作 | 适用判断 |
| --- | --- | --- | --- |
| 原生 Manifest V3 + HTML/CSS/JS | 依赖少，扩展结构直接，适合极简工具 | 自行维护构建、类型、热更新和复杂视图状态 | 可行；如果只做少量按钮和静态列表可采用 |
| WXT + React + TypeScript | 提供扩展入口约定、开发构建工具；便于管理列表与详情状态 | 增加工具链依赖，仍需理解浏览器 API 与权限 | **推荐**，适合本产品交互量与后续迭代 |

采用 **WXT 管理扩展工程，React 构建侧边栏，TypeScript 约束消息和资源数据，底层使用浏览器原生扩展 API**。页面扫描器保持普通 TypeScript 模块，不依赖 React，不绑定具体网站。

WXT 官方提供文件入口、TypeScript、开发热更新、打包及多浏览器构建支持；框架不会替代浏览器 API，也不会自动消除浏览器之间的差异。[WXT 官方](https://wxt.dev/)、[WXT 简介](https://wxt.dev/guide/introduction.html)

首版无需后端、数据库、账号系统或远程服务。版本在开发启动时按官方兼容要求确定，并提交 lockfile；本 PRD 不预设依赖的精确版本。

### 9.2 运行组件

| 组件 | 职责 |
| --- | --- |
| Background Service Worker | 工具栏事件、临时授权后的按需注入、消息校验与路由、任务和会话状态协调 |
| Content Script | 模块选取、页面高亮、普通 DOM 遍历、来源元数据提取、取消和清理 |
| Side Panel | 卡片列表、预览、详情、复制与打开地址、状态提示 |
| 共享纯函数模块 | URL 解析、去重、来源合并、字段校验 |
| 浏览器适配模块 | 包装侧边栏与相关 API，隔离 Chrome/Edge 差异 |

工具栏点击时直接调用侧边栏打开 API，随后再完成异步注入，避免在等待扫描后才尝试打开侧边栏。`sidePanel.open()` 自 Chrome 116 起提供，并要求用户操作触发。[Chrome Side Panel](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)

Chrome 技术最低版本设为 116；Edge 首版以开发验收时的稳定版和前一主版本为支持范围，核验所用 API，不推定与 Chrome 版本号完全对应。其他浏览器不列入首版兼容承诺。

### 9.3 消息和任务一致性

- 消息统一携带 `type`、`requestId`、`taskId`；背景端核对发送来源、`tabId` 与当前任务。
- 扫描任务绑定 `tabId + documentToken + taskId`，仅接收当前有效任务的结果。
- 选区以内容脚本中的实际元素引用保存，不依赖 CSS 选择器重新猜测节点。
- 结果分批发送，每批最多 100 条；总数与扫描状态单独上报。
- 开发时定义完整消息联合类型；不允许扩展成为任意 URL 请求代理。
- CSS 高亮采用独立覆盖层与隔离样式，事件退出时统一清理。

### 9.4 权限与网络策略

| 权限/能力 | 首版用途 |
| --- | --- |
| `activeTab` | 用户点击工具栏后临时访问当前页面 |
| `scripting` | 按需注入选择器和提取脚本 |
| `sidePanel` | 侧边栏界面 |
| `storage` | 保存本地偏好和浏览器会话中的结果元数据 |
| 剪贴板 | 优先使用用户点击触发的 `navigator.clipboard.writeText`；无权限或失败则提供手动复制，不预先申请 `clipboardWrite` |

首版不申请 `tabs`、`downloads`、`webRequest`、`cookies`、`<all_urls>` 或图片域名的常驻访问权限。不配置匹配全部站点的自动运行脚本。

`activeTab` 授权来自工具栏等特定用户操作；侧边栏按钮本身不作为重新授权的保证。权限失效时提示再次点击工具栏。受限页面无法通过该权限读取。[Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)

首版直接在侧边栏用图片元素加载资源，默认设置 `referrerPolicy="no-referrer"`；不额外 `fetch` 图片二进制或读取响应头。不要求 `host_permissions` 的基本显示路径仍可能因站点策略、混合内容限制或登录状态而失败。

后续如需跨域获取图片字节，须单独设计域名授权；内容脚本的跨域请求仍受同源策略约束，扩展页面或后台请求需要对应主机权限。[Chrome 跨域网络请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)

## 10. 数据与存储

### 10.1 核心数据

| 对象 | 关键字段 |
| --- | --- |
| `ExtractionTask` | `taskId`、`tabId`、`documentToken`、`pageUrl`、`pageTitle`、`moduleSummary`、`startedAt`、`status` |
| `ImageResource` | `id`、`url`、`displayName`、`formatHint`、`firstSeenOrder`、`referenceCount`、`sources`、`previewStatus` |
| `ImageSource` | `type`、`rawValue`、`elementSummary`、`alt`、`renderedWidth`、`renderedHeight`、`naturalWidth`、`naturalHeight`、`visible`、`isCandidate` |
| `ExtractionSummary` | `uniqueCount`、`referenceCount`、`skippedCount`、`visitedNodeCount`、`durationMs`、`partialReasons`、`warnings` |

`sources` 最多保存每张资源的前 20 处详情，其余只保留总计数。`elementSummary` 是可读摘要，不保存网页完整 HTML。候选来源、预览失败与尺寸未知必须独立表示，不能混为“无图片”。

### 10.2 生命周期

- 偏好设置存储在 `storage.local`，仅含视图偏好，不记录浏览历史。
- 每个标签页只保留最近一次完成的提取结果；结果元数据存储在 `storage.session`。
- 浏览器重启、扩展重新加载、禁用或更新后不保证会话结果保留。
- 图片二进制不存储到扩展存储；预览缓存交给浏览器处理。
- Service Worker 内存只做临时协调，不作为结果的唯一存储位置。
- 会话元数据总预算 5 MiB；接近预算时先淘汰其他标签页最久未查看的结果，并提示；当前结果仍超预算则截断且标记部分完成。
- 对超长字段进行限额；超过 16 KiB 的 URL 不截断为错误地址，而是跳过并说明原因。普通文本摘要按字段限制长度。

`storage.session` 是浏览器会话内存存储，适合扩展会话状态；Chrome MV3 Service Worker 可以被终止，因此状态需独立保存。[Chrome Storage](https://developer.chrome.com/docs/extensions/reference/api/storage)、[Service Worker 生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)

## 11. 非功能需求

### 11.1 性能与资源目标

以下是开发验收目标，尚未实测。应在固定测试机器、固定浏览器版本及本地测试页面上记录结果。

| 指标 | 目标与口径 |
| --- | --- |
| 悬停响应 | 交互反馈 p95 ≤ 100 ms；元素定位与高亮更新按动画帧合并 |
| 常规模块扫描 | 5,000 个元素、200 个支持的唯一地址，元数据扫描与去重 p95 ≤ 2 s；不包含远程图片加载 |
| 首批结果 | 同一测试场景下 1 s 内开始展示已发现结果，不等待所有预览完成 |
| 扫描分片 | 主动按约 8～16 ms 时间片让出主线程；避免一次同步遍历大型模块 |
| 扫描上限 | 最多 20,000 个元素或 1,000 个唯一资源；达到任一上限停止并显示部分完成 |
| 时间上限 | 扫描累计 10 s 时主动停止，展示已发现结果和限制原因 |
| 预览加载 | 同时最多启动 6 个未完成的图片加载；单项 15 s 后显示超时并终止当前尝试 |
| 大量结果 | 超过 100 张启用列表虚拟化，避免同时挂载全部图片卡片 |
| 未启动时 | 不注入页面、不扫描、不监听页面鼠标事件 |

固定场景重复运行至少 20 次；首次初始化与后续扫描分别记录。超限、取消后页面仍可正常操作，已发现结果不会被标成完整结果。

### 11.2 安全、隐私与可访问性

- 扫描和去重在本机完成，不向自建服务上传页面地址、图片链接或图片内容。
- 展示缩略图会向原图片服务器发起图片请求；这一行为在初始说明或隐私说明中明确披露。
- URL 可能包含签名或令牌，不写入生产调试日志，不设置远程埋点；复制时保留用户需要的完整地址。
- 页面文本、`alt` 和 URL 都按纯文本渲染；不拼接网页提供的 HTML，不将 SVG 作为 HTML 注入。
- 仅允许批准的 URL 协议；外链打开时避免给目标页面访问扩展窗口的能力。
- 所有脚本随扩展打包，不运行远程代码或动态求值。
- 主要按钮有明确名称、键盘焦点；列表与详情可用 `Tab` 操作，状态不只依赖颜色表达。
- 图片解码可能消耗较多内存；详情仅维持当前大图，不预加载全部大图，离开视图时释放引用。

## 12. 验收用例

建立本地受控 HTML 测试集，使用已知 DOM、地址和预期结果验收；公开网站仅作为补充冒烟测试，避免依赖其持续变化的内容。

| 编号 | 操作或前置条件 | 预期结果 |
| --- | --- | --- |
| AC-01 | 模块内 3 张图片、模块外 2 张图片 | 只得到模块内 3 个资源 |
| AC-02 | 直接选中一个 `<img>` | 能提取选中元素自身的图片 |
| AC-03 | 悬停子元素，按 `↑` 扩大、`↓` 返回，再单击锁定；通过层级路径调整并确认提取 | 单击只锁定；鼠标移动不改范围；边框和提取范围一致；网页不跳转；工具条在调整和滚动时保持位置 |
| AC-04 | 进入选择后按 `Esc` | 覆盖层移除、页面恢复交互、之前结果保留 |
| AC-05 | 同 URL 在多个元素或背景中出现 | 一张资源卡片，引用计数与来源正确 |
| AC-06 | 两个地址仅查询参数或 fragment 不同 | 保留为不同资源，参数不丢失 |
| AC-07 | 相对地址、协议相对地址、存在 `<base>` | 按文档基地址得到正确完整 URL |
| AC-08 | `picture/srcset` 根据视口选用某个地址 | 收录当前选用地址，不枚举未选候选 |
| AC-09 | 原生懒加载与指定 `data-*` 懒加载属性 | 可发现已暴露地址；候选标记明确，不改动页面属性 |
| AC-10 | CSS 多层背景与伪元素背景，包含复杂合法 URL | 正确提取 `url()`，忽略渐变；无重复或错误拆分 |
| AC-11 | 模块含隐藏的轮播图、DOM 外虚拟图片 | 隐藏 DOM 图片可收录；未生成的图片不被虚构 |
| AC-12 | 404、不可解码或站点拒绝加载 | 显示预览失败；地址仍可复制，其他卡片不受影响 |
| AC-13 | 打开详情、缩放、切换图片、返回 | 图片不裁切变形，元数据正确，返回列表保留位置 |
| AC-14 | 复制单条和全部，包括失败预览 | 内容与结果中的完整地址完全一致，批量每行一个 |
| AC-15 | 浏览器拒绝剪贴板写入 | 出现可手动复制文本，不显示虚假成功提示 |
| AC-16 | iframe、开放 Shadow DOM、`data:`、`blob:`、Canvas | 按首版边界跳过，能检测到的限制有说明，不崩溃 |
| AC-17 | 内部页、商店页、`file:` 或 PDF 查看器 | 阻止选择，给出可理解的提示 |
| AC-18 | 切换标签页、导航、取消后旧消息延迟到达 | 不串数据，不覆盖新任务；旧覆盖层与加载任务清理 |
| AC-19 | 来源模块被网页移除后重新提取 | 提示重新选择，不扫描错误的替代节点 |
| AC-20 | 重启 Service Worker、关闭再开侧边栏 | 完成结果可恢复；未完成任务明确中断，不无限加载 |
| AC-21 | 超过节点、资源、时间或会话容量限制 | 保留允许范围内的结果，说明部分完成和具体限制 |
| AC-22 | 模块无图片或只有跳过的引用 | 正确空状态、跳过信息和重新选择入口 |
| AC-23 | 包含 HTML 片段的 `alt`、危险协议地址 | 文本不执行，危险地址不打开 |
| AC-24 | 首版支持的 Chrome/Edge、窄宽侧边栏 | 主流程一致，布局无水平溢出，键盘操作可用 |

首版发布门槛：全部 P0 验收用例通过、性能目标有记录、无结果串页和网页交互无法恢复问题、构建产物可在两个目标浏览器加载。

## 14. 产品效果评估与默认决策

产品效果在本地验收和人工试用中记录，不默认添加远程数据采集：

- 核心任务完成率：能否完成选择、找到目标图并复制正确地址。
- 支持来源提取准确率：固定测试集上预期 URL 无遗漏、无模块外混入。
- 预览成功率：与提取准确率分别统计，区分地址发现和远程加载能力。
- 操作效率：记录从点击插件到成功复制目标地址的时间与选区调整次数。
- 页面影响：退出插件后网页点击、滚动、表单和导航恢复正常。

为避免后续开发反复选择，采用以下默认决策：

1. 一次提取一个模块，重新选择替换当前结果。
2. 当前图片与懒加载候选均展示，但状态明确区分。
3. 包含已在 DOM 内的隐藏图片，不自动遍历站点分页或触发加载。
4. 首版聚焦链接提取、预览和详情，下载与导出安排在 P1。
5. 默认不保存长期历史、不上传数据、不请求全站常驻访问。
6. 推荐技术栈已确定为 WXT + React + TypeScript；仅当后续出现明确约束时重新评估。

产品名称、图标和视觉风格可在开发时调整，不影响本 PRD 的核心功能与验收范围。
